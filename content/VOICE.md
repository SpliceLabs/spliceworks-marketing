# Voice

## Core Rules

1. Say it simple.
2. Say it short.
3. No sentences about sentences. Get to the point in as few words as possible.
4. Rich, dense, brief.
5. Tone should be confident and inviting.

See `VOICE-MEMO.md` for the expanded Do/Don't reference and the humanizer review protocol.

## Tone

- Confident but not boastful
- Technical but accessible
- Direct without being cold
- Inviting without being pushy

## Do

- Use "we" for Splice Works, "you" for the reader
- Use numerals always ("12 sites", "4 agents")
- Use sentence case for headings ("Read the docs")
- Use middle dot for meta ("6 Sep 2026 · 4 min")
- State outcomes clearly
- Name permissions, evidence, and limits explicitly
- Keep copy scannable

## Don't

- Never use "Unlock", "Supercharge", "Seamless", "Delve"
- Never use Title Case for headings
- Never use exclamation marks
- Never use emoji
- Never use "I"
- Never inflate claims
- Never use generic transformation language
- Never explain the writing itself

## Human Mode

When writing for humans:
- Lead with usable outcomes
- Keep evidence inspectable
- Show approval points clearly
- Make the system feel alive through agents and artifacts

## Agent Mode

When writing for agents:
- Expose capability identifiers
- Provide schemas and inputs/outputs
- State permissions and limits
- Include invocation instructions
- Use clean Markdown or structured data

## Humanizer Pass

After every draft, check:
- Does it sound like a person wrote it?
- Are there AI writing patterns to remove?
- Is the voice consistent with these rules?
- Would you say this out loud?
